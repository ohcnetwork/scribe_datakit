Scribe speech dataset · how it works

One repo on Hugging Face. Everything else is on your computer.

There's no review server. The app runs on your computer and talks to the dataset repo ohcnetwork/scribe_dataset as you, with your own Hugging Face account. The repo's files and pull requests are the only things reviewers and the maintainer share.

A claim is a pull request

When you claim a batch, the app opens a draft pull request titled [claim] <batch name>. Everyone with access can see it, so nobody else takes the same batch. The pull request's state is the batch's state.

Pull requestThe app showsMeaning
none, or all closedAvailableAnyone can claim it.
draftClaimed by you, or by someoneBeing reviewed. Nothing has been sent yet.
openSubmitted, waiting for the maintainerYour submission is in the pull request.
mergedFinished by youThe maintainer accepted it.

If two people claim the same batch at the same moment, the lower pull request number wins and the app closes the other one. Each batch in the app links to its pull request, and all claims are listed here.

What each step does on Hugging Face

The app shows what it's doing while each step runs. This is what's behind it.

  1. Connect

    Your token is checked with Hugging Face and saved on this computer by the Hugging Face library, where any Hugging Face tool on it can use it. It's never sent anywhere else.

    a few seconds

  2. Open the Batches page

    The app asks who you are, lists the files in review/batches/ and lists the claim pull requests. Choose Refresh to see claims other people made since you opened the page.

    a few seconds

  3. Claim

    The app checks nobody holds the batch, opens your draft pull request, checks again that yours came first, then downloads the batch file and, for every recording, its audio and waveform.

    The downloads take the time: a batch has 20 to 60 recordings, so that's 40 to 120 files, one after another. The app counts them as it goes. If it stops partway, what's already downloaded is kept, and Continue carries on from there.

    about a minute, longer on slow connections

  4. Review

    Nothing touches Hugging Face. Every edit is saved to review_work/<batch>/draft.json, so you can work offline and stop at any time. Continue on a batch already on this computer opens it straight away.

    instant

  5. Submit

    The app writes your text to review/submissions/<batch>.json as a commit on your pull request, then changes the pull request from draft to open. Submitting again replaces the file in the same pull request.

    a few seconds

  6. The maintainer merges

    The maintainer's script reads every open claim pull request from a listed reviewer, applies only the reviewed text, languages and category, and merges the pull request. The batch then shows as finished. The updated dataset is uploaded later.

Who sees what

Visible to others with access

Your username on the claim pull request, as soon as you claim. Your text, once you submit.

Only on your computer

Your token, and your drafts until you submit. If you lose review_work/ before submitting, the work is gone.

When Hugging Face says no

The app saysWhyWhat to do
"Your Hugging Face account can't reach …"Your account hasn't been given access to the repo, or the token is for another account.Send your username to the maintainer.
"Hugging Face is limiting requests…"Too many requests in a short time.Wait a minute, then try again.
"Can't reach Hugging Face"No internet, or it dropped.Reconnect and try again. Downloads carry on where they stopped.
"A file is missing from …"The batch points at a recording that isn't uploaded.Tell the maintainer the batch name.
"Hugging Face is having trouble"An outage on their side.Try again in a few minutes.

For maintainers: choosing the repo

The organisation and dataset come from .env in the project folder: HF_ORG=ohcnetwork and HF_DATASET=scribe_dataset. The app, review_admin.py and hf_export.py all read it. A variable set in the shell wins, so HF_ORG=me HF_DATASET=test_repo make review points one run at a test repo.
