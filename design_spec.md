# Scribe Audio Collection — Design Spec

Pre-build reference for planning the design task. Describes **what information the
platform holds and shows**, not visual styling. Numbers below are from the real
dataset (`metadata.json`, generated by `build_metadata.py`).

## 1. What this is

An open, browsable collection of scribing audio clips. Volunteers browse the
clips, read machine transcripts, correct them, categorise them, and download
either individual clips or the whole dataset. The transcription itself is
produced by a batch job (Whisper large-v3), not in the browser.

**Audience:** data contributors / volunteers. Not end consumers — the UI should
favour density, keyboard flow, and fast correction over marketing polish.

## 2. The dataset (real numbers)

| Fact | Value |
|---|---|
| Clips | 601 |
| Total audio | ~6.9 h |
| Duration: min / median / max | 0.8 s / 27.5 s / 68 min |
| Formats | 590 `webm`, 7 `mp4`, 4 `ogg` |
| Codec / sample rate | Opus, 48 kHz, mono |
| Corrupt (timestamp-damaged) clips | 44 (~7%) |
| Recording span | Feb–Jun 2026 |

Design implications:
- **Most clips are short** (median 27 s) → the list is the primary surface; the
  player is lightweight. A handful of long clips (up to 68 min) need a scrubber
  that works at both scales.
- **~7% are corrupt** — real but damaged audio. They must be *shown, flagged, and
  filterable*, never silently dropped.
- Mono/48 kHz/Opus is uniform → sample-rate display is informational, not a
  primary filter.

## 3. Data model (per clip)

One record per clip; this is exactly the shape the app consumes and the download
exports. Fields marked **derived** come from `ffprobe`/`ffmpeg`; **model** from the
transcription job; **user** are editable in the app.

All **derived** fields come from a single incremental `ffprobe`/`ffmpeg` pass
(`build_metadata.py`) that touches each file once; **model** from the
transcription job; **user** are editable in the app.

| Field | Source | Notes |
|---|---|---|
| `id` | derived | UUID prefix of the filename |
| `filename` | derived | download / playback path under `audio/` |
| `format` | derived | webm / mp4 / ogg (from extension) |
| `container` | derived | ffprobe container, e.g. `matroska,webm` |
| `codec` / `codec_long` | derived | `opus` / `Opus (Opus Interactive Audio Codec)` |
| `size_bytes` | derived | for download-size display |
| `duration_sec` | derived | corruption-corrected (see §2) |
| `bitrate_kbps` | derived | size ÷ duration; quality signal (~128 kbps typical) |
| `sample_rate`, `channels`, `channel_layout` | derived | 48000 / 1 / mono |
| `recorded_at` | derived | ISO ts parsed from filename |
| `corrupt` | derived | true = timestamp-damaged; badge + filter |
| `tags` | derived | container tags, e.g. `{encoder: "Chrome"}` — capture provenance |
| `collection` | derived | which collection the clip belongs to; set when the clip is added |
| `whisper_language` | model | Whisper's guess (e.g. `en`, `hi`); unreliable; null until transcribed |
| `spoken_languages` | user | human-confirmed list, e.g. `["ml", "en"]`; null until confirmed, and wins over `whisper_language` |
| `generated_transcript` | model | Whisper output in the spoken language; never edited |
| `generated_translation` | model | Whisper English translation; never edited; null for English-only audio |
| `final_transcript` | user | human-reviewed transcript; null until a person reviews it |
| `final_translation` | user | human-reviewed English translation; null until a person reviews it |
| `model` | model | e.g. `whisper-large-v3`; provenance of the generated text |
| `status` | user | `pending` → `reviewed` → `qa_complete` → `final`, or `flagged` (see §5) |
| `category` | user | see §4 |

Top-level doc also carries `clip_count` and `total_duration_sec` for the dataset
page headline, and `schema_version` (2).

## 4. Categories (the browse axes)

Four independent facets, all filterable and combinable:

1. **Collection** — the source batch of the clip.
2. **Language** — `spoken_languages` when confirmed, otherwise Whisper's guess. Values
   emerge from the data. Not a fixed list. A code-mixed clip appears under each language.
3. **Workflow status** — the stored `status`, except that `pending` displays as
   **Untranscribed** (no text yet) or **Needs review** (a machine draft exists). The
   Browse badge, status filter, and Categories cards render this state
   (`workflowState()` in `store.jsx`).
4. **Category** — content type. Fixed, small, sensible set:
   `medical-scribe`, `random`, `noisy-background`, `music`, `silence`,
   `test`, `uncategorized` (default). Keep it short; add only when a real
   cluster appears.

Design: facets as a persistent filter rail; each clip shows all three as chips.
Category and status are editable inline (they're `user` fields).

## 5. Verification flow

Machine text is wrong often enough that review is the core loop. `generated_*` is
always machine text and `final_*` is always human-reviewed, so the two never blur.

| Status | Meaning | Set by |
|---|---|---|
| `pending` | No human review is complete | Default |
| `reviewed` | A reviewer finished the clip, with at least one `final_*` filled | Reviewer |
| `qa_complete` | A second person checked it | QA reviewer |
| `final` | Approved for training | Maintainer only |
| `flagged` | Has a problem and needs a decision; excluded from training | Anyone |

1. Clip arrives `pending` with generated text.
2. Reviewer listens, confirms the languages, then edits or accepts each text box. A box
   left untouched stays null, so English-only annotation doesn't save the machine draft
   as human text.
3. Reviewer marks it `reviewed`. QA is optional, because reviewer numbers vary, so a
   maintainer can move `reviewed` straight to `final`.

Changing text on a `qa_complete` or `final` clip moves it back to `reviewed`.
English-only audio needs no translation; its English text is `final_transcript`.

**Persistence constraint (drives architecture):** the app is a static site over
`audio/` + `metadata.json`. There is no server. Edits therefore save to the
browser (localStorage) and are **exported as a corrections JSON** the contributor
submits (PR / upload) to be merged back into `metadata.json`. The design must make
"you have N unsaved local edits — export them" a first-class, visible state.

## 6. Pages

| Page | Shows | Key info/actions |
|---|---|---|
| **Collection list** (home) | All clips, filterable by the 3 facets + free-text search over transcript/filename | duration, language, status, category chips, mini play button; sort by date/duration/status |
| **Clip detail + player** | One clip | waveform + play/pause + scrub, full metadata table, transcript (read), links to edit / download-clip |
| **Transcribe / edit** | One clip in correction mode | player + editable transcript textarea, category/status controls, save-local + next-clip keyboard flow |
| **Category browse** | Clips grouped by a chosen facet | counts per value, click to filter the list |
| **Dataset download** | Dataset-level info | clip count, total hours, format breakdown, % verified; **download full archive** button + download `metadata.json`; explains the corrections-export contribution loop |

## 7. Player

- **Waveform** via `wavesurfer.js`, rendered from **precomputed peaks**
  (`extract_peaks.py` → `peaks/<id>.json`), not in-browser decode — the source
  webm carry no duration header and fail `decodeAudioData`. Playback runs through
  a native `<audio>` element, which decodes them fine.
- Play / pause, click-to-seek scrub, current-time / duration readout.
- Degrades gracefully: a clip with no peaks file falls back to a plain `<audio>`
  player; `corrupt` clips still show the corrupt badge rather than an error.

## 8. Download

- **Full dataset:** one archive (zip of `audio/` + `metadata.json`), pre-built by a
  script, linked as a static file. Note the size (~800 MB raw) near the button.
- **Individual clip:** direct link to the file under `audio/`.
- **Metadata alone:** `metadata.json` downloadable on its own.

## 9. Non-goals (kept out on purpose)

Accounts/auth, server-side persistence, in-browser transcription, real-time
collaboration, audio editing. The contribution loop is deliberately file-based
(export → merge) to keep the platform a static, forkable, open dataset.
